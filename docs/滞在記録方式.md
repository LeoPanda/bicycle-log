# **滞在記録方式仕様書 (bicycle-log)**

本文書は、Strava APIのアクティビティデータから30分以上の滞在地点を自動検出し、Google Places APIを用いて該当場所の名称やスポット情報を特定した上で、訪問回数・訪問日時・滞在時間をデータベース（SQLite）へ記録・集計するための仕様および技術的実現方式を定義します。

---

## **1. システム概要と目的**

### **1.1. 概要**
サイクリングやポタリング中に立ち寄ったカフェ、道の駅、休憩所などの「30分以上の滞在地点」をStravaのデータから自動抽出し、スポット情報としてデータベース化します。

### **1.2. 主な提供機能**
1. **滞在地点自動抽出**: Stravaのアクティビティデータから、移動が停止している区間（30分以上）を自動特定。
2. **スポット名称自動特定**: Google Places API (Nearby Search) を利用し、滞在座標から店舗・施設名称を特定。
3. **二重キャッシュ構造**: APIコスト削減のため、過去に訪問したスポット（近隣50m以内）は既存データを再利用。
4. **訪問統計・履歴集計**: スポットごとの訪問回数、各回の滞在時間、直近の訪問日時をデータベースで一元管理。

---

## **2. データ取得および滞在検知仕様**

### **2.1. Strava API データの選定理由**
* **Strava Polyline Map の限界**: Stravaの `summary_polyline` や `detailed_polyline` には **緯度・経度のみ** が含まれ、**時刻情報が含まれません**。そのため、「何分滞在したか」の算出が不可能です。
* **Activity Streams API の活用**: 時刻データと時系列位置情報を取得するため、**Strava Activity Streams API** を利用します。
  * **取得エンドポイント**: `GET /activities/{id}/streams`
  * **必須ストリームキー**:
    * `latlng`: 位置情報配列 `[[lat, lng], ...]`
    * `time`: アクティビティ開始時からの経過秒数配列 `[0, 1, 2, ...]`
    * `moving`: 移動中フラグ `[true, false, ...]` (補助判定に使用)

### **2.2. 滞在検知アルゴリズム (Stop Detection)**

GPSの測位誤差（揺らぎ・建物内でのブレ）を考慮し、**時空間クラスタリング** を用いて滞在地点を抽出します。

#### **判定パラメータ**
* **滞在時間閾値 ($\Delta t$)**: **1800秒 (30分) 以上**
* **滞在判定半径 ($R$)**: **半径 30m ～ 50m 以内**

#### **処理アルゴリズム手順**
1. **静止点クラスタの抽出**:
   * 時系列順に位置座標 `latlng` と経過時間 `time` をチェック。
   * ある時点 $t_A$ から $t_B$ までの座標群が指定半径 $R$ 内に収まり、かつ $(t_B - t_A) \ge 1800\text{秒}$ であれば滞在区間とみなす。
2. **滞在重心座標 (Centroid) の算出**:
   * 該当滞在区間に含まれる全位置座標の平均値から代表緯度経度 $(Lat_{stop}, Lng_{stop})$ を計算する。
3. **滞在時間および訪問日時の確定**:
   * **到着日時 (Arrived At)**: アクティビティ開始日時 + $t_A$
   * **出発日時 (Left At)**: アクティビティ開始日時 + $t_B$
   * **滞在時間 (Stay Duration)**: $t_B - t_A$ （秒単位）

## **3. Google Places API 連携 & キャッシュ構造**

Google Places API の呼び出し回数と課金を最小化するため、データベースを介したキャッシュ制御を行います。

```
[ 検出した滞在重心座標 (Lat, Lng) ]
               │
               ▼
   < 既存DB(places)の半径50m以内に > ───── (Yes) ───► [ 既存 place_id を紐付け ]
   <   登録済スポットがあるか？   >                          (API呼び出しなし)
               │
              (No)
               ▼
   [ Google Places API (Nearby Search) 呼び出し ]
               │
               ▼
   [ スポット名称・Place ID 取得 & DB保存 ]
```

### **3.1. DB内近隣スポット照合（一次キャッシュ）**
* 新たに抽出された滞在重心座標に対し、DB（`places` テーブル）内に半径 50m 以内の登録済みスポットが存在するか検索。
* 既に登録がある場合は Google API 呼び出しをスキップし、既存の `place_id` を適用。

### **3.2. Google Places API 問い合わせ（未登録スポット時）**
* DBに未登録の場合のみ、Google Places API (Nearby Search) を呼び出す。
  * **検索条件**: `location=Lat,Lng`, `radius=50`, 著名度優先 (`rankby=prominence`)
  * **主要タイプ**: `cafe`, `restaurant`, `park`, `convenience_store`, `tourist_attraction`, `food`, `point_of_interest`
* 取得した `place_id`, スポット名称 (`name`), 住所 (`address`), カテゴリを `places` テーブルに保存。

## **4. データベース設計 (SQLite)**

Litestream による GCS へのリアルタイムバックアップを前提とした SQLite スキーマ構成です。

```sql
-- 1. スポットマスターテーブル
CREATE TABLE IF NOT EXISTS places (
    id TEXT PRIMARY KEY,               -- Google Place ID または 一意のID
    name TEXT NOT NULL,                 -- スポット名称 (例: XXカフェ、OO道の駅)
    category TEXT,                      -- カテゴリ/種別
    address TEXT,                       -- 住所
    latitude REAL NOT NULL,             -- 代表緯度
    longitude REAL NOT NULL,            -- 代表経度
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 2. Stravaアクティビティテーブル
CREATE TABLE IF NOT EXISTS activities (
    id INTEGER PRIMARY KEY,             -- Strava Activity ID
    name TEXT NOT NULL,                 -- アクティビティ名
    start_date DATETIME NOT NULL,       -- 開始日時
    distance REAL,                      -- 走行距離 (メートル)
    elapsed_time INTEGER,               -- 経過時間 (秒)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 3. 滞在ログ（訪問履歴）テーブル
CREATE TABLE IF NOT EXISTS stay_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    activity_id INTEGER NOT NULL,
    place_id TEXT NOT NULL,
    arrived_at DATETIME NOT NULL,       -- 到着日時
    left_at DATETIME NOT NULL,          -- 出発日時
    stay_duration_seconds INTEGER NOT NULL, -- 滞在時間 (秒)
    stay_latitude REAL NOT NULL,        -- 当該滞在時のGPS重心緯度
    stay_longitude REAL NOT NULL,       -- 当該滞在時のGPS重心経度
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (activity_id) REFERENCES activities(id) ON DELETE CASCADE,
    FOREIGN KEY (place_id) REFERENCES places(id) ON DELETE RESTRICT
);

-- 4. 訪問統計用ビュー
CREATE VIEW IF NOT EXISTS place_visit_summaries AS
SELECT 
    p.id AS place_id,
    p.name AS place_name,
    p.category,
    p.address,
    COUNT(s.id) AS visit_count,
    SUM(s.stay_duration_seconds) AS total_stay_seconds,
    MAX(s.arrived_at) AS last_visited_at
FROM places p
JOIN stay_logs s ON p.id = s.place_id
GROUP BY p.id;
```

## **5. バックエンド & クラウドインフラ構成**

### **5.1. バックエンド仕様 (Python / FastAPI)**
* **Framework**: FastAPI
* **ORM/DBアクセス**: SQLAlchemy / SQLModel (SQLite3 Driver)
* **Strava API クライアント**: Access Token / Refresh Token の管理および Streams API の非同期フック
* **非同期処理**: Stravaデータ同期および滞在検知パイプラインは `BackgroundTasks` または 非同期タスクでバックグラウンド実行

### **5.2. Google Cloud Run + Litestream 構成**
* **Cloud Run**: アプリケーションおよび Litestream プロセスを 1 コンテナ内で実行。
* **Litestream**: SQLite WAL ログを GCS バケットへレプリケート。
  * **スケーリング設定**: コンテナ間での SQLite 書き込み競合・二重起動を予防するため `max-instances=1` に制限。
* **認証制御**: Cloud Run の Identity-Aware Proxy (IAP) によりセキュリティを確保。
