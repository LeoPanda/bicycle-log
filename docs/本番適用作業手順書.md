# **本番適用作業手順書 (PRODUCTION DEPLOYMENT GUIDE)**

## **1. 概要と単一統合コンテナアーキテクチャ**

本ドキュメントは、「自転車走行・滞在記録システム (bicycle-log)」を Google Cloud 上の本番環境 (Cloud Run) へ移行・適用するための、人間と AI 共同開発エージェント（Antigravity）の共同作業手順書である。

本システムは、個人利用における「極低コスト運用」と「データの高信頼な安全保管」を両立するため、**フロントエンド (React / Vite ビルド成果物)、バックエンド (FastAPI)、および SQLite 変更ログ非同期同期ツール (Litestream) を同一の Docker イメージ（単一統合コンテナ）にパッケージ化し、Cloud Run 上で単一サービスとして稼働させるアーキテクチャ**を採用する。

また、本番環境の初期構築時には、`data/` 配下の既存データベース（`app.db`）およびマスタ登録スクリプトから初期データを全自動ロードする。

```
 [ インターネット (PC / スマホ) ]
        │ (HTTPS / GCP Cloud Run IAP (Identity-Aware Proxy) 認証)
        ▼
   [ Cloud Run (単一統合コンテナ) ]     <-- 最小インスタンス=0 / 最大インスタンス=1 (書き込み競合防止)
   │  - FastAPI (8000ポート / REST API + 静的SPA配信 `/app/static`)
   │  - React SPA (フロントエンド静的ビルド成果物)
   │  - Litestream (バックグラウンドレプリケーションプロセス)
   │    │                                     │
   │    │ (WAL 変更ログ非同期同期)            │ (画像一元管理・アップロード/参照)
   │    ▼    ▼                                     ▼
 [ Cloud Storage (Litestream用GCS) ]    [ Cloud Storage (画像用GCS) ]
   (gs://[PROJECT_ID]-bicycle-log-litestream-       (gs://[PROJECT_ID]-bicycle-log-images)
    backend)
```

## **2. ローカル `.env` から本番環境変数への移行チェック**

ローカル環境（`backend/.env` / `.env`）に設定されている環境変数を精査し、本番環境への適用区分（Cloud Run 環境変数 vs Secret Manager シークレット vs GCP サービスアカウント）を以下のように定義する。

| 環境変数名                           | ローカル設定値例             | 本番移行区分           | 本番適用方法 / 説明                                                                         |
| :----------------------------------- | :--------------------------- | :--------------------- | :------------------------------------------------------------------------------------------ |
| **`APP_VERSION`**                    | `1.2`                        | **Cloud Run 環境変数** | `APP_VERSION=1.2`（システムカレントバージョン一元管理）                                     |
| **`TZ`**                             | `Asia/Tokyo`                 | **Cloud Run 環境変数** | `TZ=Asia/Tokyo`（全コンテナ内タイムゾーン統一）                                             |
| **`LOG_LEVEL`**                      | `INFO`                       | **Cloud Run 環境変数** | `LOG_LEVEL=INFO`（本番ログレベル。動的変更可能）                                            |
| **`DATABASE_URL`**                   | `sqlite:////app/data/app.db` | **Cloud Run 環境変数** | `DATABASE_URL=sqlite:////app/data/app.db`                                                   |
| **`GCS_BUCKET_NAME_IMAGES`**         | `bicycle-log-images`         | **Cloud Run 環境変数** | `[PROJECT_ID]-bicycle-log-images`（各種画像保存用バケット）                            |
| **`GCS_LITESTREAM_BACKUP_BUCKET`**   | `litestream-backend`         | **Cloud Run 環境変数** | `[PROJECT_ID]-bicycle-log-litestream-backend`（Litestream同期先バケット）              |
| **`VITE_GOOGLE_MAPS_API_KEY`**       | `AIzaSyC...`                 | **ビルド時環境変数**   | フロントエンド静的ビルド時に注入（Google Maps JS API用）                                     |
| **`INTERNAL_AI_TOKEN`**              | `ai_agent_secret...`         | **Secret Manager**     | Secret Manager より動的注入 (`INTERNAL_AI_TOKEN`)                                           |
| **`STRAVA_CLIENT_ID`**               | `192720`                     | **Secret Manager**     | Secret Manager より動的注入 (`STRAVA_CLIENT_ID`)                                          |
| **`STRAVA_CLIENT_SECRET`**           | `5109ebd8...`                | **Secret Manager**     | Secret Manager より動的注入 (`STRAVA_CLIENT_SECRET`)                                      |
| **`STRAVA_REFRESH_TOKEN`**           | `3d2a1c00...`                | **Secret Manager**     | Secret Manager より動的注入 (`STRAVA_REFRESH_TOKEN`)                                      |
| **`GOOGLE_PLACES_API_KEY`**          | `AIzaSyC...`                 | **Secret Manager**     | Secret Manager より動的注入 (`GOOGLE_PLACES_API_KEY`)                                      |
| **`GOOGLE_APPLICATION_CREDENTIALS`** | `/app/credentials/...`       | **Cloud Run IAM 権限** | Cloud Run サービスアカウント (ADC) に GCS アクセス権限 (`roles/storage.objectAdmin`) を付与 |

## **4. フェーズ別詳細デプロイ手順**

### **PHASE 1. 前提条件の確認**

- `gcloud` CLI で本番対象プロジェクトが選択済みであること（`gcloud config list project`で`[PROJECT_ID]`を確認）。
- 本手順書の`[PROJECT_ID]`を本番環境のプロジェクトIDに置換して実行すること。

---

### **PHASE 2. APIの有効化とインフラの初期構築（Antigravity担当）**

#### **1. 必要APIの全自動有効化**

```bash
gcloud services enable \
    run.googleapis.com \
    artifactregistry.googleapis.com \
    secretmanager.googleapis.com \
    storage.googleapis.com \
    iap.googleapis.com \
    logging.googleapis.com
```

#### **2. Dockerイメージ格納用リポジトリの作成 (Artifact Registry)**

```bash
gcloud artifacts repositories create bicycle-log-repo \
    --repository-format=docker \
    --location=asia-northeast1 \
    --description="自転車走行・滞在記録システム 本番統合Dockerリポジトリ"
```

#### **3. Litestream レプリケーション用 & 画像保存用 GCS バケットの作成**

```bash
# Litestream SQLite レプリケーション用バケット
gcloud storage buckets create gs://[PROJECT_ID]-bicycle-log-litestream-backend \
    --location=asia-northeast1 \
    --uniform-bucket-level-access

# 各種画像保存用バケット
gcloud storage buckets create gs://[PROJECT_ID]-bicycle-log-images \
    --location=asia-northeast1 \
    --uniform-bucket-level-access
```

---

### **PHASE 3. 認証鍵・機密情報の安全な構築（ハイブリッド担当）**

`APIキー安全管理・一元化設計書.md` に基づき、ローカル `.env` で保持している機密情報を Secret Manager に登録し、Cloud Run のサービスアカウントに必要な権限を付与する。

```bash
# 1. AI駆動ロギング・自律デバッグ用内部認証トークン、Strava APIクレデンシャル、およびGoogle Place APIキー
echo -n "[YOUR_INTERNAL_AI_TOKEN]" | gcloud secrets create INTERNAL_AI_TOKEN --data-file=- --replication-policy="automatic"
echo -n "[YOUR_STRAVA_CLIENT_ID]" | gcloud secrets create STRAVA_CLIENT_ID --data-file=- --replication-policy="automatic"
echo -n "[YOUR_STRAVA_CLIENT_SECRET]" | gcloud secrets create STRAVA_CLIENT_SECRET --data-file=- --replication-policy="automatic"
echo -n "[YOUR_STRAVA_REFRESH_TOKEN]" | gcloud secrets create STRAVA_REFRESH_TOKEN --data-file=- --replication-policy="automatic"
echo -n "[YOUR_GOOGLE_PLACES_API_KEY]" | gcloud secrets create GOOGLE_PLACES_API_KEY --data-file=- --replication-policy="automatic"

# 2. Cloud Run デフォルトサービスアカウントへの GCS / Secret Manager 権限付与
PROJECT_NUMBER=$(gcloud projects describe [PROJECT_ID] --format='value(projectNumber)')

# GCS オブジェクト操作権限 (画像アップロードおよびLitestream同期)
gcloud projects add-iam-policy-binding [PROJECT_ID] \
    --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
    --role="roles/storage.objectAdmin"

# Secret Manager アクセス権限
for SECRET in INTERNAL_AI_TOKEN STRAVA_CLIENT_ID STRAVA_CLIENT_SECRET STRAVA_REFRESH_TOKEN GOOGLE_PLACES_API_KEY; do
    gcloud secrets add-iam-policy-binding $SECRET \
        --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
        --role="roles/secretmanager.secretAccessor"
done
```

---

### **PHASE 4. フロント＆バック統合パッケージング・Litestream 設定・デプロイ（Antigravity担当）**

#### **1. ローカルおよび本番ビルド・反映手順 (Docker Compose 運用)**

AGENTS.md で定義されている標準運用フロー：

```bash
# 1. フロントエンド静的ファイルのビルドと同期
cd frontend
node ./node_modules/vite/bin/vite.js build
cp -r dist/* ../backend/static/
cd ..

# 2. Docker コンテナのビルドおよび再起動
docker compose up -d --build

# 3. コンテナ動作状態の確認
docker compose ps
```

#### **2. Cloud Run デプロイ手順 (Cloud Run 運用時)**

```bash
# Docker 認証の設定
gcloud auth configure-docker asia-northeast1.pkg.dev

# ビルド
docker build -f Dockerfile.prod -t asia-northeast1.pkg.dev/[PROJECT_ID]/bicycle-log-repo/app:latest .

# プッシュ
docker push asia-northeast1.pkg.dev/[PROJECT_ID]/bicycle-log-repo/app:latest

# Cloud Run デプロイ (単一統合コンテナ / max-instances=1 固定)
gcloud run deploy bicycle-log \
    --image=asia-northeast1.pkg.dev/[PROJECT_ID]/bicycle-log-repo/app:latest \
    --region=asia-northeast1 \
    --platform=managed \
    --allow-unauthenticated \
    --max-instances=1 \
    --min-instances=0 \
    --set-env-vars=APP_VERSION=1.2,DATABASE_URL=sqlite:////app/data/app.db,TZ=Asia/Tokyo,LOG_LEVEL=INFO,GCS_BUCKET_NAME_IMAGES=[PROJECT_ID]-bicycle-log-images,GCS_LITESTREAM_BACKUP_BUCKET=[PROJECT_ID]-bicycle-log-litestream-backend \
    --set-secrets=INTERNAL_AI_TOKEN=INTERNAL_AI_TOKEN:latest,STRAVA_CLIENT_ID=STRAVA_CLIENT_ID:latest,STRAVA_CLIENT_SECRET=STRAVA_CLIENT_SECRET:latest,STRAVA_REFRESH_TOKEN=STRAVA_REFRESH_TOKEN:latest,GOOGLE_PLACES_API_KEY=GOOGLE_PLACES_API_KEY:latest
```

## **5. 本番セキュリティ設定の検証 (Checklist)**

デプロイ後、セキュリティ設定およびアクセス制御を以下のチェックリストに基づき自動/手動検証する：

- [x] **1. 認証 (IAM / IAP) の確認**:
  - IAM ロールおよび Cloud Run IAP (Identity-Aware Proxy) が適切に設定されているか。
- [x] **2. Context-aware アクセスポリシー・ユーザー権限の確認**:
  - `Principal` 列に対象アクセスユーザーのメールアドレスが正しく付与されているか。
- [x] **3. パブリックアクセスの制御**:
  - 不要な `AllUsers` アクセス権が排除され、アクセスが制限されているか。
- [x] **4. 動作疎通テスト**:
  - 画面アクセス（フロントエンドSPA表示）、ヘルスチェックAPI (`GET /api/health`)、各種CRUD APIが正常に動作するか。

## **6. 運用のガバナンスとマイグレーション**

1. **`data/` 初期データロード**: 初回本番コンテナ起動時、GCS 上にバックアップデータが存在しない場合は `entrypoint.sh` が `data/app.db` を全自動でロードし、既存データ・マスタ定義をすべてリストアした状態で稼働を開始する。
2. **リアルタイム同期とレプリケーション**: リストア完了後、すべての書き込み変更は Litestream により WAL 変更ログとして GCS バケット (`gs://[PROJECT_ID]-bicycle-log-litestream-backend`) へリアルタイム非同期同期される。
3. **複数インスタンス書き込み衝突の防止 (`max-instances=1`)**: Cloud Run のスケール設定で最大インスタンス数を `max-instances=1` に厳格制限する。
4. **GCS 画像一元管理**: 各種写真は GCS バケット (`gs://[PROJECT_ID]-bicycle-log-images`) に保存・一元管理する。
5. **AI駆動ロギングと動的ログレベル調整**: 障害発生時、`POST /api/internal/logger/level` に対し `INTERNAL_AI_TOKEN` を付与してリクエストすることで、ログレベルを `DEBUG` へ動的変更可能。
