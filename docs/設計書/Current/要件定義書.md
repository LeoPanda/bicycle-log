# 要件定義書 (bicycle-log)

## 1. システムの概要

### 1.1 システムの呼称
本システムは **bicycle-log** と呼称します。

### 1.2 目的
本システムは、自転車（サイクリング/ポタリング）のアクティビティデータおよび立ち寄り地点（カフェ、道の駅、公園等）の滞在記録を自動的に抽出・管理・可視化し、個人の走行履歴や訪問スポットを一覧および地図上で一元管理することを目的とします。

### 1.3 対象ユーザーおよび運用形態
本システムは個人（または特定の管理者）による利用を前提としたウェブアプリケーションであり、Google Cloud (Cloud Run) 上で運用されます。

### 1.4 2層プロファイル体系の選定 (Profile A)

system-dev-pipeline V2.6 の2層プロファイル体系に基づき、本システムは **Profile A (サーバーレス極小コストWeb型 / ゴールデンパス)** を採用します。

#### 【プロファイル選定ディシジョンツリー】
1. **ホスティング環境**: クラウド公開かつ常時稼働ではなく、リクエストに応じた自動スケーリングと極小コスト運用（月額数十円〜無料枠）が求められる ➔ **Google Cloud Run**
2. **データベース選定**: 高価なフルマネージド RDB (Cloud SQL) を避け、単一コンテナで完結する超軽量・ゼロ運用コスト RDB を採用 ➔ **SQLite 3 (WAL モード)**
3. **データ永続化・ディザスタリカバリ**: SQLite 単体ではコンテナ再起動でデータ消失するため、秒単位の WAL ストリーミングバックアップを採用 ➔ **Litestream + Google Cloud Storage (GCS)**
4. **スキーママイグレーション**: 手動 DDL 事故を物理排除し、安全なスキーマ変更とロールバックを実現 ➔ **Alembic マイグレーション管理**
5. **認証・アクセス制御**: 個人専用システムとしての安全性を担保しつつ認証コードの肥大化を防止 ➔ **Google Cloud Identity-Aware Proxy (IAP) 二重署名検証**
6. **フロントエンドアーキテクチャ**: 高速な画面遷移とリッチな地図・グラフ表現 ➔ **React SPA (Vite) + Tailwind CSS + MSW (モックアダプター)**

## 2. システム機能要件

### [REQ-F01] 自転車・ギア管理機能
- **自転車マスタ登録・更新・削除**: 所有する自転車の識別情報（Bike ID、名称、ブランド、モデル、登録日、メモ等）を画面から CRUD 操作可能とする。
- **走行距離・積算管理**: 自転車ごとに紐づくアクティビティの走行距離・獲得標高・走行回数を自動集計・積算表示する。
- **デフォルトバイク設定**: 新規アクティビティ取り込み時に優先して割り当てられるデフォルト自転車を設定可能とする。

### [REQ-F02] Strava 連携・アクティビティ自動同期機能
- **OAuth2 認証**: Strava API の OAuth 2.0 (Access Token / Refresh Token) による認可連携を行う。
- **自動同期トリガー**: 同日初回アクセス時または手動同期ボタン押下時に、最新のアクティビティ一覧 (`GET /athlete/activities`) を取得し未登録データを自動保存する。
- **時系列 Streams API データの取得・解析**:
  - `GET /activities/{id}/streams` から `latlng`（位置座標）、`time`（経過秒数）、`moving`（移動フラグ）を取得・保存する。
  - GPS Encoded Polyline (`summary_polyline`) を解析・デコードし、走行軌跡を保持する。

### [REQ-F03] 滞在スポット自動検知・手動記録機能
- **時空間クラスタリングによる滞在検知 (Stop Detection)**:
  - 位置座標群が半径 30m〜50m 以内に留まり、かつ経過時間が **30分 (1800秒) 以上** 移動停止している区間を滞在地点として自動検出する。
  - 滞在区間の GPS 重心座標、到着日時 (`arrived_at`)、出発日時 (`left_at`)、滞在時間（秒）を算出して記録する。
- **発着点（スタート・ゴール）滞在スポット化**:
  - アクティビティの開始点座標および終了点座標を抽出し、滞在時間0秒の StayLog 2件（スタート・ゴール）を自動記録する。
  - 既存アクティビティに対する一括遡及登録 API (`POST /api/strava/backfill-endpoints`) を提供する。
- **二重キャッシュ構造による Google Places API 連携**:
  - 検出重心座標から自システム DB (`places`) の半径 50m 以内を検索（一次キャッシュ）。
  - 未登録時のみ `Google Places API (Nearby Search)` を呼び出し、スポット名称・カテゴリ・住所を取得して保存。未特定時は仮登録し画面からの手動編集を可能とする。
- **手動記録・インライン編集**:
  - 画面上から滞在スポット名称、コメント、訪問日時の手動追加・インライン編集を可能とする。

### [REQ-F04] 走行ログ・写真ギャラリー管理機能
- **アクティビティ一覧・詳細**: 走行ログ一覧（日付、距離、標高、時間、平均速度）の表示、ページネーション、ソート、詳細モーダル表示。
- **写真添付・アップロード**:
  - 滞在ログに対して複数枚の写真を添付可能とする。
  - バックエンドで自動的に WebP フォーマット（品質80%）へリサイズ・圧縮し、Google Cloud Storage (GCS) へ安全にアップロード・保存する。
  - 外部 Web 画像 URL の直接紐付けもサポートする。
- **走行ログ削除・カスケード整合性**: 走行ログ削除時に関連する滞在ログ、写真レコード、GCS上の実画像ファイルを不整合なくアトミックに削除する。

### [REQ-F05] 定番ルート登録・マッチング機能
- **幾何学的類似度判定 (Haversine 照合 & 高速枝刈り)**:
  - GPS Encoded Polyline (`summary_polyline`) の点列間球面距離を照合し、類似度が 70% を超えるアクティビティ同士を自動抽出・グルーピングする。
  - 走行距離比率（30%超乖離の即時スキップ）、バウンディングボックス枝刈り、点列事前キャッシュ、早期終了（30%超不一致での即時脱出）により、大規模データでも高速実行を保証する。
- **Strava 同期時自動紐付け**: 新規同期アクティビティが既存の定番ルートと 70% 以上の類似度を持つ場合、自動的に当該ルート配下へ紐付ける。
- **マスタ管理・代表 Polyline 表示**:
  - 定番ルートの名称編集、代表 Polyline の地図プレビュー、配下アクティビティ一覧の表示モーダルを提供する。

### [REQ-F06] 統計分析・ダッシュボード機能
- **サマリーメトリクス可視化**: 総走行距離、総上昇量、総移動時間、総ライド回数、消費カロリーの5大メトリクスカード表示。
- **多角的グラフ可視化**: 自転車別・期間別（年間・月間・週間）の横棒カプセル型プログレスバーによる視認性の高い推移グラフ表示（走行距離、獲得標高、移動時間、回数、カロリーのタブ切替）。
- **Google Maps 滞在マップ & クラスタリング**:
  - 滞在スポットをカテゴリ別アイコンでマーカープロット表示。
  - 近接マーカーのクラスタリング（件数バッジ表示）。
- **走行軌跡ヒートマップ & 定番ルート可視化**:
  - 全走行ログの Polyline を重ね合わせたヒートマップ表示。全画面拡大時の自動リサイズ追従、スポットのカテゴリ別アイコン表示、bicycle-log内詳細画面へのダイレクト遷移リンクボタン、グレースケール表示（デフォルト有効）。
  - 地図下部に定番ルート一覧カードを配置し、走行回数の把握および詳細モーダルへの直接遷移を提供。
- **ダッシュボード横断検索**: トップバナー検索窓から滞在スポット・定番ルートをリアルタイムサジェスト検索し、ワンクリックで詳細へ直接遷移。

### [REQ-F07] マスタ設定機能
- **滞在カテゴリマスタ管理**: カフェ、レストラン、公園、道の駅、コンビニ等の自動判別用カテゴリ定義・アイコン設定。
- **タグマスタ管理**: アクティビティやスポットに付与するカスタムタグの作成・編集・色分け管理。
- **外部 API / システム設定**: Strava クレデンシャル、Google Maps / Places API キー、環境設定の一元確認・管理。

## 3. システム非機能要件 (定常コア8項目)

### [REQ-NF01] Anti-God Component / 行数制限 (Hard Gate)
- **フロントエンド行数制限**: React コンポーネントは **1ファイル最大250行** を厳格に遵守し、責務ごとに Hooks、UI コンポーネント、Services を物理分離する。
- **バックエンド行数制限**: バックエンドモジュール・モデルは **1ファイル最大400行** を厳格に遵守する。
- **機械遮断**: Git `pre-commit` フックおよび CI ゲートで `harness_guard.py` を実行し、行数違反をコミット前に物理遮断する。

### [REQ-NF02] 要件トレーサビリティ (RTM 100% カバレッジ & 異常系 20% 以上)
- **トレーサビリティ機械検証**: 要件定義 `[REQ-*]` から基本設計書群、およびテストコードまでのカバレッジ 100% を `traceability_checker.py` により機械検証する。
- **異常系テスト比率**: 全自動テストケース中、異常系・境界値テスト比率 **20% 以上** を必須条件とする。

### [REQ-NF03] ブラウザ感覚センサー (WCAG AA & エラーゼロ)
- **コンソールエラーゼロ**: ブラウザ検証において、Chrome DevTools Console Error が 0 件であることを機械的・感覚的に検証する。
- **アクセシビリティ (A11y)**: WCAG 2.1 AA コントラスト比（4.5:1 以上）、適切な ARIA ラベル、キーボードナビゲーションを適合させる。

### [REQ-NF04] 型定義自動同期 (OpenAPI ➔ TypeScript Codegen)
- **型の一貫性**: バックエンド FastAPI の Pydantic スキーマから OpenAPI JSON を決定論的に生成し、フロントエンド TypeScript 型定義を自動生成・同期する。
- **手動型二重定義の排除**: API 通信部において `any` 型や手動 DTO 二重定義を禁止する。

### [REQ-NF05] シークレット厳格検証 (Pydantic Settings 起動時即死ガード)
- **起動時バリデーション**: `pydantic-settings` を用いて、必須環境変数（`DATABASE_URL`, `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET`, `GOOGLE_MAPS_API_KEY` 等）が未設定または不正な場合、サーバー起動時に即死（Fail-Fast）させる。
- **フロントエンド秘匿化**: クライアントへ GCP サービスアカウントキーや外部シークレットを一切渡さない。

### [REQ-NF06] 統一タイムゾーン (Aware UTC 保存 / JST 表示)
- **保存方針**: データベース（SQLite）にはタイムゾーン情報付き UTC (Aware UTC) でミリ秒精度まで保存する。
- **表示方針**: API レスポンスおよびフロントエンド画面表示はすべて **日本標準時 (JST, UTC+9 / Asia/Tokyo)** へ決定論的に変換して表示する。

### [REQ-NF07] モック制御アダプター層 (MSW 集約 & 実結合フォールバック禁止)
- **直書きモック排除**: フロントエンドコンポーネント内にモックデータ（ダミー配列・オブジェクト）を直書きすることを絶対禁止し、MSW (Mock Service Worker) ハンドラーへ一元集約する。
- **環境変数切替**: `VITE_ENABLE_MOCK=true/false` により、同一コードベースでモックモードと実バックエンド結合モードを完全透過的に切り替える。
- **サイレントフォールバック禁止**: 実結合モード（`VITE_ENABLE_MOCK=false`）時に通信エラーとなった際、モックへサイレントフォールバックすることを物理遮断する。

### [REQ-NF08] 画面グランドデザイン (4px/8px グリッド & 明暗ペア & デイライト視認性)
- **グリッド規範**: 余白（Padding / Margin）およびサイズは 4px / 8px の倍数グリッドに統一する。
- **明暗ペア指定**: すべての UI 要素において、ライトモードとダークモードのカラーペア（Tailwind CSS `dark:`）を網羅する。
- **デイライト視認性**: 屋外日光下でも十分な視認性を確保できる高コントラスト設計（テキスト最低コントラスト比 4.5:1）を適用する。

## 4. 外部インターフェース要件

### 4.1 Strava API
- **認証**: OAuth 2.0 (Access Token / Refresh Token)
- **使用エンドポイント**:
  - `GET /athlete/activities` (アクティビティ一覧取得)
  - `GET /activities/{id}/streams` (時系列位置・時間ストリームデータ取得)

### 4.2 Google Places API
- **使用サービス**: Nearby Search API
- **目的**: 滞在判定座標からのスポット名称・カテゴリ・住所自動取得 (50m 検索)

### 4.3 Google Cloud Storage (GCS)
- **用途 1**: 添付写真の保存 (WebP 80% 圧縮変換後の画像ファイル)
- **用途 2**: Litestream による SQLite バックアップ WAL ストレージ

### 4.4 Google Cloud Run & Identity-Aware Proxy (IAP)
- **ホスティング環境**: Cloud Run 単一統合コンテナ (`max-instances=1`)
- **認証レイヤー**: IAP (コンテキストアウェアアクセスポリシー、JWT二重検証)
