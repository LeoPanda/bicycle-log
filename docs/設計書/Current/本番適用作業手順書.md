本ドキュメントは、「自転車走行・滞在記録システム (bicycle-log)」を Google Cloud 上の本番環境 (Cloud Run) へ移行・適用するための標準手順書である。

- **対応要件**: `[REQ-NF02]`, `[REQ-NF05]`, `[REQ-NF06]`, `[REQ-NF07]`
- **採用プロファイル**: Profile A (サーバーレス極小コストWeb型: Cloud Run + Litestream + SQLite WAL + Alembic + React SPA + Tailwind CSS)

```
 [ インターネット (PC / スマホ) ]
        │ (HTTPS / GCP Cloud Run IAP (Identity-Aware Proxy) 認証) [REQ-NF05]
        ▼
   [ Cloud Run (単一統合コンテナ) ]     <-- 最小インスタンス=0 / 最大インスタンス=1 (書き込み競合防止)

   │  - Litestream (バックグラウンドレプリケーションプロセス)
   │    │                                     │
   │    │ (WAL 変更ログ非同期同期)            │ (画像一元管理・アップロード/参照) [REQ-F04]
   │    ▼                                     ▼
 [ Cloud Storage (Litestream用GCS) ]    [ Cloud Storage (画像用GCS) ]
   (gs://[PROJECT_ID]-bicycle-log-litestream-backend)
```

## 3. 本番デプロイおよび Alembic マイグレーション実行手順

```bash
# 1. Cloud Build による本番統合コンテナイメージのビルド & プッシュ
gcloud builds submit --config=cloudbuild.yaml .

# 2. Cloud Run デプロイ (max-instances=1 固定、SQLite WAL & Litestream レプリケーション運用)
gcloud run deploy bicycle-log \
    --image=asia-northeast1-docker.pkg.dev/leopandaaiplayground/bicycle-log-repo/app:v2.1.0 \
    --region=asia-northeast1 \
    --platform=managed \
    --allow-unauthenticated \
    --max-instances=1 \
    --min-instances=0 \
    --update-env-vars=APP_VERSION=2.1.0 \
    --quiet
```

### 3.1 本番コンテナ起動時フェイルセーフ仕様 (`entrypoint.sh`)
1. **Litestream GCS リカバリ**: コンテナ起動時に GCS バケットから最新の SQLite DB および WAL ログを `/app/data/app.db` に復元。
2. **Alembic Baseline 自動スタンプ**: v1.2 以前の既存本番 DB（`bikes` テーブルが存在し `alembic_version` が未作成の環境）を検知した場合、自動的に `alembic stamp 0001` を実行してベースラインを登録。
3. **マイグレーション自動適用**: `alembic upgrade head` を実行し、未適用のマイグレーション（例: `0002_add_api_cache_table`）を差分適用してスキーマを最新化。
4. **Litestream レプリケーション常時監視**: `litestream replicate` 経由で FastAPI (`uvicorn`) を起動し、書き込み WAL をリアルタイムに GCS へレプリケーション。
