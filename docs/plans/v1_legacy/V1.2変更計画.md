# V1.2 システム変更計画書

本ドキュメントは、システムバージョン **1.2** における機能拡張およびUI/UX改善に関する変更計画および実装設計書である。ユーザーレビューおよび確定指示に基づき策定された。

---

## 1. 計画概要

### 1.1 改訂の背景と目的
本システム（bicycle-log）は、Strava のアクティビティおよび GPS ログから滞在スポットを検出し、走行ログ・定番ルートとともに可視化・分析するプラットフォームである。  
バージョン 1.2 では、データの網羅性向上（開始点・終了点のスポット化）、バージョン視認性の担保、ダッシュボードからのクイックアクセス（検索機能）、および可視化／分析画面における地図操作性と情報アクセスの向上を目的として、以下の4つの主要改訂を実施する。

### 1.2 改訂項目一覧
1. **走行ログの開始点・終了点の滞在スポット追加**
   - アクティビティの `summary_polyline` から開始点および終了点の座標を抽出。
   - 既存のダブルキャッシュ検出ロジック（DB `places` 検索 → Google Places API 検索）と連携してスポット（Place）を特定・生成。
   - アクティビティに紐づく滞在ログ（StayLog）として**スタートとゴールで2件**記録（周回コースで同一Placeの場合も時系列で2件登録）。
   - **初期処理用の一括検出API**（全activities対象）および**通常処理（Strava同期連動）**の両方をサポート。
2. **トップバーへのカレントバージョン表記**
   - `.env` の `APP_VERSION=1.2` と連動し、トップバーのタイトルの隣にカレントバージョン（`v1.2`）を表示。
3. **ダッシュボードへの検索窓設置**
   - ダッシュボードのタイトルバー領域に検索窓を新設し、滞在スポットおよび定番ルートをリアルタイムサジェスト方式で横断検索・詳細遷移可能にする。
4. **可視化／分析（SCR-05）画面のヒートマップ機能拡張**
   - ヒートマップに全画面フルスクリーン拡大トグルボタンを新設。
   - ルートクリック時、下部一覧へのフォーカスだけでなく、スポット情報と同様に地図上にサブウィンドウ（オーバーレイカード）を表示し、該当詳細への導線を確保。

## 2. 各変更項目の詳細設計

### 2.1 走行ログの開始点・終了点の滞在スポット追加

#### 2.1.1 座標抽出ロジック
- アクティビティに保存されている `summary_polyline` をデコードし、座標列 `[(lat_0, lng_0), ..., (lat_N, lng_N)]` を取得する。
  - **開始点座標**: 最初のポイント `(lat_0, lng_0)`
  - **終了点座標**: 最後のポイント `(lat_N, lng_N)`
- polyline が存在しない、またはポイント数が不足している（2点未満の）場合は処理を安全にスキップする。

#### 2.1.2 スポット（Place）特定・生成
- 既存の `app.services.places_service.get_or_create_place_for_stop(session, lat, lng, search_radius_meters=50.0)` を適用。
  - **第1キャッシュ**: ローカル DB `places` から 50m 以内の既存スポットを検索。ヒットした場合はそれを再利用。
  - **第2キャッシュ / 外部API**: Google Places API (New) Nearby Search により施設名・カテゴリ・住所を自動取得して新規スポット登録。
  - **フォールバック**: 施設が見つからない場合は「未分類の滞在スポット」として登録。

#### 2.1.3 滞在ログ（StayLog）の登録仕様
- 開始点および終了点に対して、それぞれ `StayLog` を生成してコミットする。
  - **開始点ログ**:
    - `activity_id`: 対象アクティビティID
    - `place_id`: 抽出された Place ID
    - `arrived_at`: アクティビティの `start_date`
    - `left_at`: アクティビティの `start_date`
    - `stay_duration_seconds`: 0
    - `stay_latitude`, `stay_longitude`: 開始点座標
    - `notes`: `"{place.name} (スタート地点)"`
  - **終了点ログ**:
    - `activity_id`: 対象アクティビティID
    - `place_id`: 抽出された Place ID
    - `arrived_at`: `start_date + timedelta(seconds=activity.elapsed_time or activity.moving_time)`
    - `left_at`: 同上
    - `stay_duration_seconds`: 0
    - `stay_latitude`, `stay_longitude`: 終了点座標
    - `notes`: `"{place.name} (ゴール地点)"`
- **周回コース・同一地点の扱い**: 開始点と終了点が同一スポット（50m以内）であっても、スタート時ログとゴール時ログの**合計2件**を独立したレコードとして登録する。
- **重複防止**: 既に当該アクティビティに `(スタート地点)` または `(ゴール地点)` のメモを持つ StayLog が存在する場合は二重登録を行わない。

#### 2.1.4 API設計
1. **通常同期処理の組み込み**:
   - `app.services.strava_service.sync_strava_activities` 内で、新規アクティビティ登録時およびストリーム滞在検出後に、開始点・終了点の滞在スポット検出・StayLog登録を実行。
2. **初期処理・遡及適用API（新規）**:
   - `POST /api/strava/backfill-endpoints`
   - クエリパラメータ: `all_activities: bool = True`, `limit_months: Optional[int] = None`
   - 既存のアクティビティを走査し、未登録のスタート・ゴール滞在スポットおよびログを一括生成・補完。

### 2.2 トップバーへのカレントバージョン表記

#### 2.2.1 バージョン情報の管理と供給
- `.env` 内の `APP_VERSION=1.2` を唯一の情報源とする。
- バックエンドの `backend/app/core/config.py` に `APP_VERSION: str = "1.2"` を追加。
- システム情報エンドポイント `GET /api/system/version` を新設し、`{"version": settings.APP_VERSION}` を返却。

#### 2.2.2 フロントエンド表示設計
- `Header.tsx` において、`bicycle-log` タイトルの右横にバージョンバッジを表示。
- 表記形式: `v1.2`
- デザイン:
  ```tsx
  <span className="px-2 py-0.5 text-[11px] font-bold rounded-full bg-blue-100 dark:bg-blue-900/60 text-blue-700 dark:text-blue-300 border border-blue-200 dark:border-blue-800 tracking-wide">
    v{version}
  </span>
  ```

### 2.3 ダッシュボードへの検索窓設置

#### 2.3.1 画面配置とレイアウト
- ダッシュボード（`DashboardPage.tsx`）のトップバナー（青紫グラデーションエリア内）のタイトルと操作ボタンの間に検索窓コンポーネントを配置。

#### 2.3.2 検索対象とAPI仕様
- **バックエンドAPI**: `GET /api/search?q={query}`
  - **滞在スポット（Place）**: 名称、住所、カテゴリ名での部分一致検索（最大10件）
  - **定番ルート（Route）**: 定番ルート名での部分一致検索（最大10件）
  - レスポンス構造:
    ```json
    {
      "places": [
        {
          "id": "place_xxx",
          "name": "カフェ〇〇",
          "category_name": "カフェ",
          "address": "東京都...",
          "visit_count": 5
        }
      ],
      "routes": [
        {
          "id": 1,
          "name": "多摩川サイクリングロード",
          "activity_count": 8
        }
      ]
    }
    ```

#### 2.3.3 UIインタラクション（リアルタイムサジェスト方式）
- 検索窓に文字を入力（300ms デバウンス）すると直下にドロップダウン候補リストを表示。
- 「滞在スポット」と「定番ルート」の2つのセクションにアイコン付きで分類。
- 候補クリック時の画面遷移:
  - 滞在スポット: `/items/{place_id}?type=place` へ遷移
  - 定番ルート: `/master?tab=routes&route_id={route_id}` へ遷移（または定番ルート詳細モーダルを開く）
- 枠外クリックまたは Esc キーでサジェストドロップダウンをクローズ。

---

### 2.4 可視化／分析（SCR-05）画面のヒートマップ変更

#### 2.4.1 全画面フルスクリーン拡大機能
- 地図コンテナ右上に「全画面拡大」トグルボタン（`Maximize2` / `Minimize2`）を設置。
- 拡大モード有効時:
  - `fixed inset-0 z-50 bg-slate-900/95 p-4 flex flex-col` として画面全体にマップを展開。
  - ヘッダーバーにコントロール類（閉じる/縮小ボタン、年選択、スポット表示/グレースケールトグル）を配置。
  - Leaflet の `map.invalidateSize()` を実行し、全画面にスムーズにフィット。

#### 2.4.2 ルートクリック時の地図上サブウィンドウ表示
- 地図上のルート（定番ルートまたは単体アクティビティの Polyline）をクリックした際、マップ内（左下オーバーレイ）にサブウィンドウ（情報カード）を表示。
- **定番ルート選択時（`selectedRoute`）のサブウィンドウ表示**:
  - タイトル: 定番ルート名
  - 情報: 走行回数（`走行回数: 〇回`）
  - アクションボタン:
    - 「定番ルート詳細（モーダル展開）」
    - 「マスタ管理へ（`/master?tab=routes&route_id=...`）」
- **単体アクティビティ選択時（`selectedPolyline`）のサブウィンドウ表示**:
  - タイトル: アクティビティ名
  - 情報: 走行日、走行距離（`〇〇 km`）
  - アクションボタン:
    - 「アクティビティ詳細へ（`/items/{activity_id}?type=activity`）」
- 右上の閉じるボタン（✕）でサブウィンドウを閉じ、選択状態を解除。

## 3. データベースおよびスキーマへの影響分析

| テーブル名 | 変更内容 | 備考 |
| :--- | :--- | :--- |
| `places` | スキーマ変更なし | 既存テーブルをそのまま利用 |
| `stay_logs` | スキーマ変更なし | 開始点・終了点を `stay_duration_seconds=0` として格納 |
| `activities` | スキーマ変更なし | 既存の `summary_polyline` をデコードして利用 |
| `routes` | スキーマ変更なし | 検索および表示仕様のみ変更 |

※ 既存のDBスキーマに対する破壊的変更やマイグレーション列の追加は不要。

## 5. シナリオテスト計画概要

改訂実行後、`/tests/V1.2シナリオテスト結果レポート.md` を作成し、以下の項目を検証する。

| テスト項目 | 検証内容 | 判定基準 |
| :--- | :--- | :--- |
| 開始点・終了点スポット化（通常同期） | アクティビティ同期時に開始点・終了点が滞在ログとして生成されること | アクティビティ詳細画面でスタート・ゴールの滞在ログが各1件ずつ計2件表示されること |
| 開始点・終了点スポット化（遡及処理） | `POST /api/strava/backfill-endpoints` 実行時に全既存アクティビティに適用されること | 既存アクティビティ詳細でスタート・ゴールの滞在ログが確認できること |
| バージョン表記 | トップバーにカレントバージョンが表示されること | `v1.2` がヘッダーに視認でき、`.env` の `APP_VERSION` と一致すること |
| ダッシュボード検索（サジェスト） | 検索窓からスポット名・ルート名を入力した際、候補がリアルタイムにサジェスト表示されること | 候補一覧が表示され、クリック時に目的の詳細画面へ遷移できること |
| ヒートマップ全画面拡大 | ヒートマップの拡大ボタンをクリックした際、マップ領域が全画面表示されること | 地図が全画面モーダルで表示され、タイルのズレなく操作可能で、縮小ボタンで復帰すること |
| ルートサブウィンドウ | ヒートマップ上のルートをクリックした際、地図上に情報カードが表示されること | ルート名・統計情報が表示され、詳細リンクから画面遷移できること |
