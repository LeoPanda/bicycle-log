## 1. システム総合レビュー（dev-review-system）の実施

担当: 🛡️ `qa-engineer`

本番リリース直前ゲートとして、以下の 6 大観点を厳格に監査する。

### 監査観点
1. **本番モックOFF二重防御**:
   - `Dockerfile.prod` および本番ビルドにおいて `VITE_ENABLE_MOCK=false` が強制され、MSW がバンドルから完全に除外されていること。
2. **IAP JWT 署名検証有効化**:
   - 本番環境で `X-Goog-IAP-JWT-Assertion` 検証が確実に機能し、開発用バイパスが無効化されていること。
3. **平文シークレット・未置換プレースホルダーの排除**:
   - ソースコードおよびコミット対象ファイルに API キー、パスワード、秘密鍵が生値で含まれていないこと。
4. **Alembic 起動時保証**:
   - コンテナ起動スクリプト（`entrypoint.sh`）で `alembic upgrade head` が実行され、スキーマ不整合時にコンテナが即死フェイルセーフすること。
5. **データ保全・ロールバック計画の完全性**:
   - 万一の障害時に直前のスナップショットから原子的に復旧できる手順が整備されていること。
6. **要件トレーサビリティの完全性**:
   - `traceability_checker.py --mode full` が PASS していること。

- 成果物: `docs/reports/システム総合レビュー結果報告書_v2.1.0.md`
- 必須判定: **`RELEASE APPROVED`**

```bash
python3 scripts/state_manager.py record-review system "RELEASE APPROVED" docs/reports/システム総合レビュー結果報告書_v2.1.0.md
```

## 2. Docker コンテナ起動と検証環境の確立

担当: 👑 プロジェクトコンダクター

```bash
# 1. フロントエンド静的ビルドと同期
cd frontend
node ./node_modules/vite/bin/vite.js build
cp -r dist/* ../backend/static/
cd ..

# 2. Docker コンテナの完全再構築・起動
docker compose down
docker compose up -d --build

# 3. 稼働状態確認（backend, frontend, sqlite-web がすべて Up であること）
docker compose ps
```

## 3. ユーザーによる実ブラウザ視認レビュー

ユーザー自身がブラウザにて `http://localhost:8000`（または設定ポート）へアクセスし、以下の観点で視認操作レビューを行う。

### ユーザー視認チェックリスト
- [ ] **ダッシュボード画面**:
  - サマリカードの数値、最近のアクティビティ一覧が正しく表示されるか。
- [ ] **アクティビティ詳細・滞在スポット画面**:
  - 地図描画、GPSポリライン、滞在スポットマーカーが正常にレンダリングされるか。
  - 写真ギャラリーおよび写真アップロードが機能するか。
- [ ] **分析画面**:
  - 月間走行距離グラフ、滞在カテゴリ円グラフ、ヒートマップが崩れずに描画されるか。
- [ ] **マスタ設定画面**:
  - 自転車一覧、カテゴリ、タグの設定がスムーズに行えるか。
- [ ] **画面グランドデザイン・視認性**:
  - 4px/8px グリッドの整列感、文字と背景のコントラスト、ダークモード/ライトモードの切り替えが美しいか。

## 4. 視認レビューフィードバック・修正サイクル

ユーザーから表示崩れ、操作の違和感、色味の調整等のフィードバックがあった場合、以下の修正サイクルを迅速に回す。

1. 👑 コンダクターが指摘事項を整理し、修正タスクを起票。
2. 🎨 `ui-designer` または 💻 `backend-engineer` が修正を実施（250行/400行制限を維持）。
3. フロントエンド再ビルド ➔ `docker compose up -d --build` で即時反映。
4. ユーザーへ再確認を依頼し、合格承認を得る。
